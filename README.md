## 版本规则

产品版本与前端静态资源修订统一使用语义化版本号（`v主版本.次版本.修订版本`，例如 `v3.1.1`）；不再使用独立的递增资源编号。数据库 `schema_version` 仅随数据库迁移变化，和产品版本分开维护。

部署在极空间 Docker 上、供 Android 浏览器使用的文字记账应用。手机在本地完成语音转文字，本应用只接收文字，不调用麦克风、不上传录音。

## 可选：DeepSeek 口语语义补全

默认仍使用本地关键词和规则解析，断网可用。配置 DeepSeek 后，系统仅把你已确认提交的**转写文字**发送给 DeepSeek，用于补全不规范口语里的分类、地点、消费内容和“是否加满”；金额、升数、里程、油号和记录时间始终由本地规则与入账校验把关。补全字段会标为“请核对”，模型不会直接写账。

在极空间的项目目录创建权限为 `600` 的 `.env` 文件（不要提交 GitHub）：

```dotenv
DEEPSEEK_API_KEY=你的DeepSeek_API_Key
DEEPSEEK_MODEL=deepseek-flash
```

随后重新构建并启动 Compose。密钥和模型原始响应不会写入 SQLite、Excel、Git 或应用日志；转写原句仍沿用现有账本规则保存并可导出、修改。未配置密钥、网络不可用、超时或模型返回格式不合规时，自动退回纯本地规则，不影响记账。

## 当前功能

- 开始/结束行程，出发时默认满油并强制填写出发里程。
- 通过快捷分类直接填写，或解析本地语音转写文字；覆盖吃饭餐饮、衣物、住宿、油费、过路费、停车、门票娱乐、日用补给、购物特产、其他交通、旅行服务和车辆费用。
- 首页只保留总支出、用车成本、行驶里程、百公里油耗和每公里成本五个指标，并按分类展示累计金额。
- “过路费”分类显示为“ETC”；每笔记录增加“消费内容”，用于记录具体买了什么或支付了什么。
- “消费内容”的填写示例会根据所选一级分类自动变化。
- 每笔账保存可修改的消费时间；地点在所有分类中均可填写。手机通过 HTTPS 打开时，可主动点击“GPS定位”，离线匹配中文大致地区，并保存地区、经纬度和定位精度；应用不会自动定位，也不调用第三方地图。
- 已打开过应用且已缓存当前行程时，无网络也能通过快捷分类新增消费。记录先保存在手机浏览器，恢复与极空间的连接后自动同步；每笔使用唯一编号防止重试造成重复。
- 进行中行程的每笔历史消费都可修改或删除；修改会复用同一套入账校验，删除前会二次确认，成功后立即重新计算页面指标。
- “出发里程”指车辆出发时仪表盘显示的累计总里程（ODO），不是本次行程填0；当前行程卡可同时修改行程标题和出发里程，系统会同步重算相关指标。
- 加油表单保留支付金额、油号、升数、挂牌单价（可选）和当前里程；挂牌油价、实付折算金额与优惠差额分别保存。是否加满默认为“未确认”，只有可靠连续满箱区间才计算油耗。
- 可一键导出当前进行中行程的标准 Excel（`.xlsx`），包含“行程汇总”“消费明细”“里程记录”“每日行程”“回收站”“修改历史”六个工作表；仅 `?all=1` 才会导出全量历史。
- 手机待同步记录可修改、删除或单独导出 CSV；原始文字和确认表单会自动保存草稿，只在服务端确认入账后清除。
- 消费和独立里程记录删除后进入 30 天回收站，可恢复；也可在联网且二次确认后单项永久删除。永久删除会同时清除该条修订历史，并保留仅用于防止离线重放复活的墓碑。
- 缺失项分为“必须补充、影响统计、建议补充”，同时说明缺失影响。
- 汽油只允许 95/98，默认 95；支持常见数字和中文转写形式。
- 百公里油耗只按可靠连续满箱区间计算；未确认或未加满的油费仍计入总支出和用车成本，但不会猜测油耗。
- 数据保存在 SQLite，Docker 目录映射到 `./data`。
- 三分钟内金额、分类和地点相同的流水会提示可能重复，确认后仍可保存。

## 极空间部署

1. 把整个 `roadtrip-ledger` 文件夹放到极空间的持久目录。
2. 在极空间 Docker 的 Compose 项目中导入 `compose.yaml`。
   若启用 DeepSeek，把上节的 `.env` 放在与 Compose 文件相同的目录；不要把 Key 写进 `compose.yaml`。
3. Compose 仅将 `18080` 绑定到极空间本机 `127.0.0.1`，请用 Tailscale Serve 将自己的 tailnet HTTPS 地址代理到 `http://127.0.0.1:18080`，再从已加入 tailnet 的手机访问。
4. 不要把 `18080`、数据库目录或本应用直接映射到公网。本应用没有登录系统：访问控制依赖现有 tailnet 成员与设备安全；Tailscale Serve 的 HTTPS 同源请求可以正常写入，跨站浏览器写请求会被拒绝。
5. Android 浏览器打开页面后，可使用“添加到主屏幕”。手机先用系统输入法完成本地语音转文字，再把文字提交给本应用。

端口可在 `compose.yaml` 中修改，但应保持仅绑定 `127.0.0.1`。升级前备份 `data/roadtrip.db`。

如果极空间当前无法从 Docker Hub 拉取 `python:3.12-alpine`，而本机已有
`nousresearch/hermes-agent:v2026.8.31`，可改用 `compose.zspace-offline.yaml`。
它只复用该镜像的只读基础层，不会连接或修改正在运行的 Hermes 容器。

## 里程、油耗与用车成本口径

起始油箱按满油记录。进行中的行程根据加油及独立里程记录确定当前里程，已结束的行程使用结束里程。用车成本包含本行程所有有效油费、ETC 和停车费，不会扣除出发里程处的加油支出。

```text
行驶里程 = 当前（或结束）里程表读数 − 出发里程表读数
用车成本 = 油费 + ETC + 停车费
每公里成本 = 用车成本 ÷ 行驶里程
百公里油耗 = 可靠满箱区间的累计升数 ÷ 对应累计里程 × 100
```

用车成本和每公里成本随有效记录更新，不要求末次加满；行驶里程为零或缺失时不计算每公里成本。油耗仅使用明确加满且升数、里程齐全的连续可靠区间；未加满、加满状态未知或缺少必要字段会中断该区间，下一次明确加满作为新边界。没有可靠区间时显示数据不足，不使用累计购油量猜测油耗。

## 本地运行与测试

```bash
python3 app.py
python3 -m unittest discover -s tests -v
# 已安装 Playwright 时：node tests/browser_full_acceptance.cjs
```

`browser_full_acceptance.cjs` 会自行创建临时 SQLite 数据库和仅监听 `127.0.0.1` 的服务，覆盖完整数据生命周期、GPS mock 和窄/宽屏及软键盘可达性；不会连接生产服务或手机。

打开 `http://127.0.0.1:8080`。

## MVP 限制

- 退款、押金尚未实现状态流转；系统会明确阻止其被当成普通消费保存。
- 暂不包含多人分摊、票据识别、GPS轨迹、精确街道/商户反向解析和用户登录；中文地区是根据内置行政区坐标离线估算的大致结果。
- 总支出包含本行程所有有效消费；用车成本包含油费支出、ETC 和停车费，不代表按油箱余量核算的实际燃油消耗成本。每公里成本为用车成本除以行驶里程。
- 油耗依赖可靠满箱区间及完整升数、里程；缺少必要信息时会明确提示需要补充。
- 静态页面可安装到主屏幕；离线新增消费会在手机浏览器持久化成功后才清空表单，恢复连接后按固定编号同步。浏览器存储被系统清理或设备遗失的恢复能力仍需依赖导出备份。
- 多个标签页同时离线记账时，应用使用浏览器的 Web Locks 串行化队列读写；不支持该能力的旧浏览器会拒绝离线写入，以避免覆盖已有记录。
